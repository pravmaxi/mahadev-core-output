# Trading Setup Panel - Core Logic & State Machine

This document is the absolute source of truth for the `trading_setup.html` Virtual Panel. It defines exactly how UI settings affect the engine, how every column is calculated, and the strict flow of the 4-step state machine.

## 1. UI Settings (Left & Top Panels)

### Left Panel: Strategy & Sizing
*   **Total Capital & Allocations:** The `Alloted Amount` per symbol is used to calculate Qty. `Qty = int(Alloted Amount / Fill Price)`. No fractional shares.
*   **Profit Target %:** Used to calculate the `TARGET` column.
*   **Stop Loss %:** Used to calculate the `STOP LOSS` column. If set to `0`, the SL defaults to the `OPP SIGNAL`.
*   **Max Market Gap %:** If the difference between `LTP` and `TRIGGER LVL` is greater than this %, the `VALID` column becomes `NO`, and the signal is ignored.
*   **Wait Max Bars:** If a Limit order sits in `PAPER ORDER` and the price never crosses the trigger within this many bars, the order is cancelled (Expired).
*   **Trailing Stop Loss:** 
    *   *Enable:* Toggles trailing logic.
    *   *Start %:* The profit % required to activate the trailing SL.
    *   *Step %:* The distance the SL follows the price.
    *   *Behavior:* Once activated, SL moves dynamically with the LTP. If user manually edits Target/SL in the UI, trailing SL is disabled for that trade.

### Top Panel: Routing & Scanning
*   **Paper Trade / Live Trade:** Toggles whether to execute the order in the virtual ledger or send it to Zerodha.
*   **Send to Queue:** If UNCHECKED, disk I/O is bypassed (ultra-fast scanning). The UI updates virtually, but no JSON queues are written.
*   **Allow Market Orders:** If unchecked, Market orders might be blocked or converted to Limits (based on auto-trader logic).
*   **Auto-Scan & Interval:** If Auto-Scan is OFF, the engine only runs exactly one scan on start, then waits for manual triggers.

## 2. Column Definitions & Rules

### Signal Columns (From Indicator)
*   **WT ACTION:** The string generated by the WT Indicator (e.g., "Sell Limit Order (BO close 290.31)"). It is purely a display of the indicator's calculation.
*   **TRIG STATUS:** "New Trigger" if a fresh cross occurred, else "—".
*   **VALID:** Shows `YES (Gap X%)` or `NO (Gap X%)` based on the Max Gap % setting.
*   **TRIGGER LVL:** High (for Buy) or Low (for Sell) of the valid signal candle.

### State Machine Columns
*   **ORDER QUEUE:** 
    *   Receives the `WT ACTION` string ONLY if `TRIG STATUS == "New Trigger"` AND `VALID == "YES"`.
    *   Holds only ONE item at a time. A new signal overwrites the queue.
*   **PAPER ORDER:**
    *   The active order. Displays the exact same string as `ORDER QUEUE`.
    *   If empty, it instantly pulls the value from `ORDER QUEUE`.
    *   *Cancellation Rule:* If a pending Limit order exists here, and a new signal enters `ORDER QUEUE`, the pending order is cancelled (logged as "Cancelled" with 0 P&L), cleared, and the new signal is promoted.
    *   `ORDER TRIG PRICE` is hidden (`—`) while pending.
*   **POSITION:**
    *   Shows `LONG X` or `SHORT Y` once filled.
    *   Shows `Pending` while a Limit order is waiting.
    *   Shows `—` when flat.
*   **POS IN PROGRESS:**
    *   `YES` only when an order is filled and position is active.
    *   `NO` if flat or waiting for a Limit fill.

### Risk & P&L Columns
*   **ORDER TRIG PRICE:** Populates ONLY when `POS IN PROGRESS == YES`. It is locked to the LTP at the exact moment of the fill.
*   **TARGET & STOP LOSS:** Calculated based on `ORDER TRIG PRICE` (not the original signal level). 
*   **OPP SIGNAL:** The newest opposite valid signal. If a pending opposite limit order exists, its trigger price becomes the Opp Signal.
*   **ORDER P&L:** Live floating P&L of the active position: `(LTP - ORDER TRIG PRICE) * Qty`.
*   **TOTAL P&L:** Accumulated P&L from closed trades. Resets only when the user clicks "Reset Signals".

## 3. The Logic Flow Tree (Per Tick)

```text
[START: New Tick / Scan for Symbol]
 │
 ├── 1. SIGNAL GENERATION (WT Indicator)
 │    │
 │    ├── Calculate WT Action & Trigger Level
 │    ├── Calculate Gap % (LTP vs Trigger Level)
 │    │
 │    ├──► Is Gap > Max Gap %?
 │    │    ├── [YES] ──► Mark "NO (Gap)", SKIP to end of tick.
 │    │    └── [NO]  ──► Continue.
 │    │
 │    ├──► Is TRIG STATUS == "New Trigger" AND VALID == "YES"?
 │    │    ├── [YES] ──► Action: Move WT ACTION string to ORDER QUEUE.
 │    │    └── [NO]  ──► Continue.
 │    │
 │    ▼
 ├── 2. ORDER QUEUE -> PAPER ORDER (The Handoff)
 │    │
 │    ├──► Is ORDER QUEUE empty (—)?
 │    │    ├── [YES] ──► SKIP to Step 3.
 │    │    └── [NO]  ──► Check PAPER ORDER.
 │    │
 │    ├──► Is PAPER ORDER occupied by a PENDING LIMIT order?
 │    │    ├── [YES] ──► Action: Cancel pending order. 
 │    │    │            Log to History (Reason: Cancelled, P&L: 0).
 │    │    │            Clear PAPER ORDER.
 │    │    └── [NO]  ──► Continue.
 │    │
 │    ├──► Is PAPER ORDER empty?
 │    │    ├── [YES] ──► Action: Move ORDER QUEUE value to PAPER ORDER.
 │    │    │            Clear ORDER QUEUE.
 │    │    └── [NO]  ──► SKIP to Step 3.
 │    │
 │    ▼
 ├── 3. PAPER ORDER EXECUTION (The Fill)
 │    │
 │    ├──► Is PAPER ORDER empty?
 │    │    ├── [YES] ──► SKIP to Step 4.
 │    │    └── [NO]  ──► Check Order Type.
 │    │
 │    ├──► Is Order Type == MARKET?
 │    │    ├── [YES] ──► Action: Fill instantly at LTP. Go to Step 3.5.
 │    │    └── [NO]  ──► Is Order Type == LIMIT?
 │    │
 │    ├──► Did LTP Cross Limit Trigger Price?
 │    │    ├── [YES] ──► Action: Fill at Trigger Price. Go to Step 3.5.
 │    │    └── [NO]  ──► Check Expiry.
 │    │
 │    ├──► Has Wait Max Bars Expired?
 │    │    ├── [YES] ──► Action: Cancel Limit Order. 
 │    │    │            Log to History (Reason: Expired, P&L: 0).
 │    │    │            Clear PAPER ORDER. SKIP to Step 4.
 │    │    └── [NO]  ──► Action: Keep waiting in PAPER ORDER. SKIP to Step 4.
 │    │
 │    ├── 3.5 ON FILL (The Setup)
 │    │    ├── Calculate Qty: int(Alloted Amt / Fill Price) -> (Can be 0)
 │    │    ├── Update POSITION column (LONG X / SHORT Y)
 │    │    ├── Set POS IN PROGRESS = "YES"
 │    │    ├── Lock ORDER TRIG PRICE = Fill Price
 │    │    ├── Clear PAPER ORDER column
 │    │    └── Calculate TARGET & SL based on ORDER TRIG PRICE
 │    │
 │    ▼
 └── 4. POSITION MANAGEMENT & EXIT
      │
      ├──► Is POSITION empty (—)?
      │    ├── [YES] ──► END TICK.
      │    └── [NO]  ──► Calculate Live ORDER P&L (LTP vs ORDER TRIG PRICE).
      │
      ├──► Apply Trailing SL (If enabled and Start % reached).
      │
      ├──► Did LTP hit TARGET, STOP LOSS, or OPP SIGNAL?
      │    │
      │    ├── [NO] ──► Update floating P&L in UI. END TICK.
      │    │
      │    └── [YES] ──► EXIT SEQUENCE (The Clear Slate):
      │         ├── 1. Bank P&L into TOTAL P&L.
      │         ├── 2. Log to History (Reason: Target / SL / Opp Signal).
      │         ├── 3. Clear POSITION column.
      │         ├── 4. Clear POS IN PROGRESS column.
      │         ├── 5. Clear ORDER TRIG PRICE column.
      │         ├── 6. Clear TARGET, STOP LOSS, and OPP SIGNAL columns.
      │         └── 7. LOOP BACK TO STEP 2 (Instantly check ORDER QUEUE).
      │
      ▼
     [END TICK]
